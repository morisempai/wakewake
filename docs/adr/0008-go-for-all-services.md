# ADR-0008: Go for all services

**Status:** Accepted
**Date:** 2026-07-16
**Accepted:** 2026-07-26
**Deciders:** morisempai
**Related:** ADR-0001 (supersedes its stack choice only), ADR-0002, ADR-0003, issue #3

## Context

ADR-0001 chose TypeScript/NestJS with pnpm workspaces + Nx as the implementation stack. It is
still `proposed` and was never signed off. No service code exists — `services/` contains six
`CLAUDE.md` files and nothing else — so the stack is not yet load-bearing and the cost of
changing it is close to zero. This window closes as soon as M2 writes the first handler.

> **Acceptance note (2026-07-26):** the Context above is the 2026-07-16 snapshot that made the
> switch cheap. Go has since been implemented across M1.5 and M2 — all five services are Go — while
> this ADR sat `proposed` for want of a stated rationale. This acceptance records that rationale
> (below); it formalizes a decision already carried out rather than opening a fresh one.

### Rationale (stated by the decider)

Go was chosen for three properties weighed as decisive:

- **Strict, small syntax.** Go's deliberately minimal surface and an uncompromising compiler —
  unused imports and variables are errors, error returns are explicit, `gofmt` enforces one
  canonical form — narrow the room for stylistic drift and a class of runtime surprises. Across
  five services authored by separate agents, that uniformity is worth more than expressive
  flexibility.
- **Execution speed.** Compiled native binaries with low startup and per-request latency serve the
  latency targets in `docs/nfr.md` (booking-hold p99 = 1 s) with headroom.
- **Resource efficiency.** A small memory footprint and static binaries yield small container
  images, matching the per-service container model in `infra/` and lowering per-service running
  cost.

These are the forces the decider stated. They act against a documented backdrop that Go also
serves: `docs/nfr.md` targets 99.9% availability and RPO=0; ADR-0003 puts the double-booking
invariant in Postgres, so the service layer around it is thin; ADR-0007 requires OpenTelemetry in
every service. Contracts in `contracts/` are language-neutral (OpenAPI 3.1 + AsyncAPI 3.0) and
constrain no implementation language.

## Decision

We will implement all services in **Go** (single version pinned in `go.work`), replacing
TypeScript/NestJS. The monorepo, contract-first, and data-ownership decisions in ADR-0001 stand
unchanged; only its stack choice is superseded. Module layout is a Go workspace (`go.work`) with
one `go.mod` per service, replacing pnpm workspaces + Nx. Node.js remains in the repo **solely**
to run the contract linters (Spectral, AsyncAPI CLI), which lint YAML and are unaffected by the
service language; `.nvmrc` and the lint CI jobs stay as they are.

## Consequences

- (+) The language switch costs six `CLAUDE.md` rewrites and five config files. Contracts, CI
  lint, ADRs 0002–0007, and `infra/` are untouched — the contract-first bet paying out exactly
  as intended.
- (+) Static binaries and small images suit the per-service container model in `infra/`.
- (+) `pgx` exposes Postgres error codes directly, so ADR-0003's exclusion-constraint violation
  (SQLSTATE 23P01) maps to `409 reservation_overlap` without ORM translation.
- (−) **We lose Nx's affected-graph**, which ADR-0001 listed as a CI benefit. Go has no drop-in
  equivalent; CI must either build everything or reimplement change detection via `paths:`
  filters. This is a real regression in CI cost and was a stated reason for choosing Nx.
- (−) NestJS supplied DI, module structure, config validation, and request pipelines for free.
  In Go these are hand-rolled or assembled from libraries, so `service-template` must be
  rewritten and the first service will be slower, not faster.
- (−) Two toolchains now live in the repo (Go for services, Node for contract linting). Anyone
  cloning it must install both to run the full check suite locally.
- (−) Typed clients must be generated by `oapi-codegen` rather than the TypeScript generator
  ADR-0001 assumed; the `shared/` generation step in M1's plan is not yet written for either.
- (−) `.claude/skills/service-template` and `.claude/skills/testing-standards` are written for
  TypeScript and are now wrong. They are inside `.claude/`, which hard rule #1 forbids agents
  from editing — see the blocking note in the migration PR.

## Alternatives considered

- **Keep TypeScript/NestJS** — rejected. No fault was found with TypeScript itself; Go was
  preferred for the three forces in Rationale (stricter syntax, faster execution, lower resource
  use). The cost of the switch is real and recorded in Consequences — chiefly the loss of Nx's
  affected-graph.
- **Go for new services, TypeScript for existing** — rejected: no TypeScript services exist, so
  this would be a split toolchain bought for nothing.
- **Rust** — not evaluated; not proposed.
